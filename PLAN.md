# CineBoard — архитектура и рабочий план

> Черновик. Статус: **работаем локально**. Бэкенд и соцчасть (этап 3) отложены до отдельного решения — сначала разберёмся с безопасностью данных. Пункты с ❓ — открытые решения.

## 0. Продукт

CineBoard — «Pinterest для фильмов», социальная сеть о кино.
- **Профиль**: имя, bio, любимые фильмы (топ), публичные подборки.
- **Подборки**: тематические, публичные или приватные, с обложкой.
- **Оценки и отзывы**: пользователь ставит фильму оценку и пишет отзыв; у фильма виден рейтинг сообщества и отзывы других.
- **Соцсвязи**: подписки, лента, лайки (этап 3, после выбора бэкенда).
- Каталог фильмов — TMDB (как источник данных, не как «мнение сообщества»: оценки TMDB и оценки пользователей CineBoard показываем раздельно).

## 1. Что есть сейчас (as-is)

- iOS 17+, SwiftUI, SwiftData, Observation (`@Observable`), без внешних зависимостей, проект из `project.yml` (XcodeGen).
- **Модели**: `UserAccount` → `MovieCollection` → `CollectionItem` (снимок фильма: id, название, год, постер, рейтинг). `Movie` — DTO из TMDB.
- **Сервисы**: `TMDBClient` (протокол `MovieCatalog`), `AppSession` (регистрация/вход, PBKDF2), `CollectionService` (CRUD с проверкой владельца), `DemoSeeder`.
- **UI**: 4 вкладки — Лента, Поиск, Подборки, Профиль; детали фильма и подборки, редактор, шит «Сохранить в подборку».
- Аккаунты **только локальные**: чужие подборки видны лишь как демо-данные.

### Замеченные слабые места
1. `AppSession` и `CollectionService` лежат в одном слое с UI-логикой; Views напрямую ходят в SwiftData/сервисы — вьюмоделей нет, тестировать логику экранов трудно.
2. Нет кэша каталога и защиты от гонок при поиске (debounce/отмена) — проверить в `MovieList.swift`.
3. Пароль/сессия: хэш в SwiftData, id сессии в `UserDefaults` — для локального режима ок; с сервером это заменяется на Keychain + токены.
4. Фильмы в подборке — снимки, не обновляются; жанры/описание офлайн недоступны.
5. Тесты: один файл, покрытие неясно.

## 2. Целевая архитектура

Слои (зависимости только сверху вниз):

```
Views (SwiftUI)  →  ViewModels (@Observable, @MainActor)  →  Services/Repositories  →  Data sources
                                                                                       ├─ SwiftData (локально)
                                                                                       ├─ TMDB (сеть)
                                                                                       └─ Backend API (Supabase)
```

- **Domain**: чистые структуры/протоколы (`Movie`, `CollectionRepository`, `AuthProvider`, `MovieCatalog`). Не знают про SwiftUI и SwiftData.
- **Data**: реализации протоколов. Сегодняшний `CollectionService` → `LocalCollectionRepository`; `AppSession` делится на `AuthProvider` (локальный/серверный) и `SessionStore`.
- **Presentation**: по ViewModel на экран (Feed, Search, Collections, CollectionDetail, MovieDetail, Profile). Навигация — `NavigationStack` + enum `Route`, табы — `AppRouter`.
- **DI**: контейнер зависимостей в `CineBoardApp`, передаётся через `Environment` (как уже сделано с `\.catalog`); в тестах/превью подменяются моки.
- **Кэш**: `URLCache` для изображений + простой дисковый кэш ответов TMDB (trending, details).
- Структура папок: `App/ Domain/ Data/ Features/<Feature>/{View,ViewModel} DesignSystem/`.

### Модель данных (дополнение к текущей)
- `Review`: id, автор (`UserAccount`), `movieID`, снимок фильма (название/постер), `rating` (1–10), `text` (необязателен), `createdAt`, `updatedAt`. Уникальность: один отзыв на пару (автор, фильм).
- `FavoriteMovie`: автор, `movieID`, снимок, `position` — порядок в «любимых» (лимит, например, 10).
- Рейтинг сообщества фильма = среднее по `Review.rating` (считаем на лету / кэшируем).
- Все сущности имеют UUID и `updatedAt` — готовность к будущей синхронизации.
- Права: автор редактирует/удаляет только свои отзывы и избранное; чужие публичные данные — только чтение (по аналогии с `CollectionService.authorize`).
