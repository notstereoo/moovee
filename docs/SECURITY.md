# CineBoard — безопасность и приватность данных

Статус: локальная версия (аккаунты и данные только на устройстве). Документ описывает, что мы защищаем, от кого и что сознательно оставлено на потом (бэкенд, этап 3).

## 1. Что защищаем

| Данные | Чувствительность |
|---|---|
| Пароль пользователя (соль и PBKDF2-хэш) | высокая |
| Идентификатор сессии («кто вошёл») | высокая |
| Профиль, подборки, отзывы, оценки, любимые | средняя (личные вкусы; часть задумана публичной) |
| Кэш каталога TMDB | низкая (публичные данные) |
| Ключ TMDB API | низкая (только чтение каталога), но не должен попадать в репозиторий |

## 2. От кого защищаем

1. **Потеря или кража заблокированного устройства.** Нужно, чтобы данные нельзя было прочитать с диска.
2. **Другой человек с доступом к разблокированному телефону.** Нельзя тихо удалить аккаунт, подобрать пароль перебором, перехватить чужую сессию подменой файла.
3. **Резервные копии и перенос данных.** Секреты не должны лежать в базе или `UserDefaults`, которые попадают в бэкапы в открытом виде.
4. **Утечка через репозиторий и логи.** Секреты не в git, чувствительные данные не в логах.
5. **Другие пользователи приложения** (в будущем при общей базе): видят только то, что владелец сделал публичным.

Вне модели угроз: взлом самой iOS, jailbreak, вредоносное ПО с правами root, злоумышленник с разблокированным устройством **и** знанием пароля.

## 3. Что сделано

| Угроза | Мера | Где в коде |
|---|---|---|
| Хэш пароля читается из базы/бэкапа | Соль и хэш хранятся только в Keychain (`kSecAttrAccessibleAfterFirstUnlock`); поля в SwiftData остаются пустыми. Старые данные переносятся при запуске | `SecretStore`, `LocalAuthProvider.migrateLegacyCredentials` |
| Подмена сессии правкой `UserDefaults` | Идентификатор сессии — в Keychain; старый ключ из `UserDefaults` переносится и удаляется | `AppSession` |
| Подбор пароля | После 5 неудач вход блокируется на 30 с, затем задержка удваивается (максимум 15 мин). Счётчик хранится в Keychain и переживает перезапуск; действует и для несуществующих имён | `LoginThrottle` |
| Определение существующих имён по времени ответа | Для неизвестного имени выполняется тот же PBKDF2 | `LocalAuthProvider.login` |
| Слабое хранение пароля | PBKDF2-HMAC-SHA256, 120 000 раундов, случайная соль 16 байт, сравнение за постоянное время | `PasswordHasher` |
| Чтение файла базы на заблокированном устройстве | `NSFileProtectionComplete`: entitlement `default-data-protection` для новых файлов и явная установка для существующих (`default.store`, `-wal`, `-shm`) | `CineBoard.entitlements`, `StoreProtection` |
| Хранение данных без возможности удалить | «Удалить аккаунт…» в профиле: подтверждается паролем (под тем же ограничением попыток), удаляет профиль, подборки, отзывы, любимые, секреты и сессию | `AppSession.deleteAccount` |
| Нежелательная публичность | «Закрытый профиль»: другие не видят любимые, подборки и список отзывов; подборки такого пользователя не попадают в «Открытия» и недоступны по прямой ссылке | `UserAccount.isContentVisible`, `MovieCollection.isVisible` |
| Секреты в репозитории | `Config/Secrets.xcconfig` в `.gitignore`; в git только `Secrets.xcconfig.example` | `.gitignore` |
| Секреты в логах | В коде нет `print`/`os_log` с пользовательскими данными (проверено поиском) | — |
| Чужие правки данных | Каждая изменяющая операция репозиториев проверяет владельца (`notOwner`/`notAuthor`) | `Local*Repository` |

## 4. Приватность: что видно другим

| | Открытый профиль | Закрытый профиль |
|---|---|---|
| Никнейм (@username), отображаемое имя, аватар, баннер | видно | видно |
| Bio | видно | видно |
| Число подписчиков, подписок и лайков подборок | видно | видно |
| Списки подписчиков и подписок | видно | видно |
| Кнопка «Follow» | доступна | доступна (подтверждения подписки пока нет) |
| Сохранённые чужие подборки («Saved») | только владельцу | только владельцу |
| Любимые фильмы | видно | скрыто |
| Публичные подборки | видно | скрыто |
| Приватные подборки | скрыто | скрыто |
| Список отзывов в профиле | видно | скрыто |
| Отзыв и оценка под страницей фильма | видно (с именем автора) | **видно** — отзывы остаются публичным содержимым фильма; это сказано в настройке |

Лайк и сохранение чужой подборки возможны только если подборка видна пользователю (публичная и профиль автора открыт); если автор позже её скрыл, она пропадает из «Saved». Связи (подписки, лайки, сохранения) удаляются при удалении аккаунта или подборки.

## 5. Известные ограничения (принято осознанно)

- **Фото профиля** (аватар 512×512 и баннер 1500×500, JPEG) лежат в базе (внешнее хранилище SwiftData) и защищены так же, как база (`NSFileProtectionComplete`). Выбор фото идёт через системный PhotosPicker, доступ ко всей медиатеке приложению не нужен.
- **Подписка на закрытый профиль** не требует одобрения владельца — добавим вместе с сервером.

- **Аккаунты локальные.** Это не защита от человека с физическим доступом к *разблокированному* устройству и его паролем; для настоящей многопользовательской модели нужен сервер (этап 3).
- **Восстановление из резервной копии.** Keychain попадает только в *зашифрованные* бэкапы. Если восстановить неподписанную копию на новом устройстве, профили в базе останутся, а пароли — нет: войти в такие аккаунты нельзя. Решится серверным входом.
- **Ключ TMDB лежит в приложении** (Info.plist). Его можно извлечь из установленной сборки. Ключ даёт только чтение публичного каталога; для релиза его стоит спрятать за собственным прокси.
- **Нет двухфакторной защиты и восстановления пароля.** Забытый пароль восстановить нельзя (только удалить данные приложения).
- **Face ID** не используется — осознанное решение продукта.
- Кэш каталога и изображений лежит в `Caches` и не шифруется отдельно (публичные данные).

## 6. Что понадобится вместе с бэкендом (этап 3)

- Sign in with Apple и токены доступа в Keychain; отказ от локальных паролей.
- Модерация: жалобы, блокировки, удаление контента и аккаунта на сервере.
- Ограничение запросов на стороне сервера; политика конфиденциальности и условия использования.
- Прокси для TMDB вместо ключа в приложении.
